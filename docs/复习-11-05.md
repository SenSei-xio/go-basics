# 第一部分：进制与位运算（今天补完 W4 第 1 项）

## 1.1 三种前缀

| 写法 | 读法 | 例子 |
|---|---|---|
| `0b1011` | 二进制（binary） | 11 |
| `0o17` | 八进制（octal） | 15 |
| `0x1F` | 十六进制（hex） | 31 |

- 前缀就是**"按几进制读"的标签**，就像文件的扩展名告诉你用什么打开。
- 大小写都能编译（`0B1011` 也行），但**业界一律写小写**。
- 十进制没有前缀，直接写 `11`。

## 1.2 二进制怎么读（按权重）

从**右往左**数，第 0 位权重 1，第 1 位权重 2，第 2 位权重 4，第 3 位权重 8……每往左一位**乘 2**。

```
0b1011
  │││└── 第 0 位 = 1 → 1×1  = 1
  ││└─── 第 1 位 = 1 → 1×2  = 2
  │└──── 第 2 位 = 0 → 0×4  = 0   ← 这一位是 0，不是 1
  └───── 第 3 位 = 1 → 1×8  = 8
                          合计 = 11
```

🔴 **你今天第一次答成 7**（把权重 4 那一位看成 1）。**7 是 `0b0111`**。
记法：**从右边开始数，第几位就是 2 的几次方，跟"这个数字在第几个位置"无关。**

再练几个：
- `0b1101` = 8 + 4 + 0 + 1 = **13** ✅（这个你一次就算对了）
- `0b1111` = 8+4+2+1 = **15**
- `0b10000` = **16**
- `0b11111111` = **255**

## 1.3 十六进制

`0x` 后面每一位可以是 `0~9` 和 `A~F`，共 16 个数码。

**`A` 不是字母，是"第 10 号数码"**（像扑克牌里的 J、Q、K、A）：

| 数码 | 值 |
|---|---|
| `A` | 10 |
| `B` | 11 |
| `C` | 12 |
| `D` | 13 |
| `E` | 14 |
| `F` | 15 |

**六道全对（你今天 6/6）**：
- `0x1F` = 1×16 + 15 = **31**
- `0x10` = 1×16 + 0 = **16**（🔴 不是十！）
- `0xFF` = 15×16 + 15 = **255**
- `0xA` = **10**
- `0x2A` = 2×16 + 10 = **42**
- `38` = 2×16 + 6 → **`0x26`**（反向：除 16 取余）

**反向算法（十进制 → 十六进制）**：
```
38 ÷ 16 = 2 ... 余 6
 2 ÷ 16 = 0 ... 余 2
从下往上读余数 → 2、6 → 0x26
```

## 1.4 一个十六进制位 = 四个二进制位

这条**必须刻进脑子**，看内存、看协议头全靠它：

```
0x1F = 0001 1111
        ↑↑↑↑ ↑↑↑↑
        1=F  1=F     ← 每个十六进制位拆成 4 个二进制位
```

`0xFFFF` = 16 个 1 = **65535**（这个数字你会反复见到，W5 拆协议头就要用）。
`0xFFFFFFFF` = 32 个 1 = 4294967295。

**为什么是 4 位？** 因为 4 个二进制位最大能表示 15，正好是 F。

## 1.5 五个位运算符（🔴 三个容易串位）

| 符号 | 名字 | 规则 | 口诀 |
|---|---|---|---|
| `&` | 与 | **两个都是 1 才得 1** | **有 0 就 0**（怕 0） |
| `\|` | 或 | **有一个是 1 就得 1** | **有 1 就 1**（怕 1） |
| `^` | 异或 | **两个不一样才得 1** | **挑刺：不一样才 1** |
| `<<` | 左移 | 整体往左挪，右边补 0 | **乘 2 的 n 次方** |
| `>>` | 右移 | 整体往右挪，右边挤出去扔 | **除 2 的 n 次方** |

### 🔴 三个数必须背下来（你 11-04 三个串位过）

```
12 & 10 = 8      12 | 10 = 14      12 ^ 10 = 6
1100              1100              1100
1010              1010              1010
────              ────              ────
1000 = 8          1110 = 14         0110 = 6
```

**怎么记不会串**：
- `&` 像"两道门都开才通过" → 最严格 → **结果最小**（8）
- `|` 像"任一道门开就通过" → 最宽松 → **结果最大**（14）
- `^` 夹在中间 → **结果 6**
- 而且 **8 + 6 = 14**（`a+b = (a&b) + (a|b)`，这是恒等式，可以自查！）

🔴 **你今天的错**：`^` 的**数值算对了（6），但嘴上说"两个相同才给1"**——这是**第 2 次**说反规则。

**`^` 的正确定义：两个不一样才给 1。**
- `1 ^ 1 = 0`（一样 → 0）
- `0 ^ 0 = 0`（一样 → 0）
- `1 ^ 0 = 1`（不一样 → 1）
- `0 ^ 1 = 1`（不一样 → 1）

**自己异或自己 = 0**：`5 ^ 5 = 0`。这条很有用——能用来"清零"。

**`^` 放在一个数前面是"取反"**：`^0b1011 = -12`（跟 `^` 做二元运算不是一回事）。

### 移位

```
5 << 1 = 10     5 × 2¹
5 << 2 = 20     5 × 2²
5 << 3 = 40     5 × 2³
1 << 5 = 32     1 × 2⁵   🔴 你 11-03 答成 256（多算 3 位）
```

🔴 **`1 << 5` 不是 256**：从 1 开始左移 5 次 → 1 → 2 → 4 → 8 → 16 → **32**。
**256 是 `1 << 8`。**

```
40 >> 1 = 20    40 ÷ 2
40 >> 2 = 10    40 ÷ 4
40 >> 3 = 5     40 ÷ 8
```

## 1.6 掩码表（🔴 必背，W5 天天用）

**"掩码"就是"只有某一位是 1、其余全是 0"的数**，用来"只看那一位"。

| 掩码 | 二进制 | 第几位 |
|---|---|---|
| `0x01` | `0000 0001` | 第 **0** 位 |
| `0x02` | `0000 0010` | 第 **1** 位 |
| `0x04` | `0000 0100` | 第 **2** 位 |
| `0x08` | `0000 1000` | 第 **3** 位 |
| `0x10` | `0001 0000` | 第 **4** 位 |
| `0x20` | `0010 0000` | 第 **5** 位 |
| `0x40` | `0100 0000` | 第 **6** 位 |
| `0x80` | `1000 0000` | 第 **7** 位 |

**规律**：`0x01` 是第 0 位，每往上一档就"左移一位"。**`1 << i` 就是造"第 i 位是 1"的数**：
```go
1 << 0 = 1    = 0x01
1 << 1 = 2    = 0x02
1 << 2 = 4    = 0x04
1 << 3 = 8    = 0x08
```

🔴 **你 11-03 的错**：`flags & 0x04` 你当成"第 3 位"，其实 `0x04` 是**第 2 位**（从 0 开始数！）。

## 1.7 `flags & 0x02 != 0` 到底在干什么（🔴 W4 验收点）

这是**判断"某一位是不是 1"**的标准写法。三步：

```
第 1 步：拿掩码 0x02 去 &（相当于拿一块只开了一个洞的挡板）
第 2 步：& 的规则是"有 0 就 0" → 掩码是 0 的地方，结果全被清成 0
第 3 步：掩码是 1 的那一位，原样保留
       → 那一位原本是 1，结果就是 0x02（非 0）
       → 那一位原本是 0，结果就是 0x00（等于 0）
```

**所以 `x & 0x02 != 0` 等价于"第 1 位是不是 1"。**

实跑例子（`flags = 0b00000101` = 5）：
```
flags & 0x01 != 0  → true    第 0 位是 1（在线）
flags & 0x02 != 0  → false   第 1 位是 0（不是 VIP）
flags & 0x04 != 0  → true    第 2 位是 1（禁言）
flags & 0x08 != 0  → false
```

**一句话**：`&` 把其它位全清零、只留掩码那一位的原值。**结果非 0 就是 1，结果 0 就是 0。**

## 1.8 协议头拆包（W5 核心技能）

一个 32 位的头，装了两个 16 位的东西：

```
header := 0x1F2E0085

0x1F2E0085
└──┬──┘└──┬──┘
  魔数    包长
  高16位  低16位
```

**取高 16 位（魔数）**：
```go
魔数 := uint16(header >> 16)      // 或 (header >> 16) & 0xFFFF
```
- `>> 16` 是"整排 32 格往右挪 16 格" → 原来的高 16 位移到低位
- 再用 `uint16()` 或 `& 0xFFFF` 把上面可能残留的位"挡掉"

**取低 16 位（包长）**：
```go
包长 := uint16(header & 0xFFFF)
```
- 它本来就在低位，**不用挪**，直接用挡板筛掉高 16 位

**打包（把两个 16 位拼回 32 位）**：
```go
header := uint32(魔数)<<16 | uint32(包长)
```
- `<< 16` 把魔数抬到高位
- `|` 把包长塞进空位（因为包长那部分是 0，`|` 有 1 就 1，等于直接填进去）

实跑验证：
```
header = 0x1F2E0085
header >> 16        = 0x1F2E  （魔数）
header & 0xFFFF     = 0x0085  （包长 = 133）
```

**W5 会用的四个真场景**：
| 场景 | 写法 |
|---|---|
| 魔数校验 | `header>>16&0xFFFF == 0x1F2E` |
| 包长 | `len & 0x00FFFFFF` |
| 标志位 | `flags & 0x02 != 0` |
| IP 解析 | `192.168.1.1 ↔ 0xC0A80101` |

## 1.9 位运算 vs 逻辑运算（别搞混）

| 位运算（对每个二进制位） | 逻辑运算（对整个 bool） |
|---|---|
| `&` | `&&` |
| `\|` | `\|\|` |
| `^` | （没有对应的） |
| `^x` 取反 | `!x` 取反 |

`&` 用在**数字**上 → 按位与；`&&` 用在**条件**上 → 短路与。

# 第二部分：context（今天的主课）

## 2.1 它解决什么问题

**一句话**：一个 goroutine 干活，另一个地方要能"叫停"它。

🔴 先看**没有 context 会怎样**（演示 `1_没有context.go`）：
```
后台: 还在干活，第 1 次
后台: 还在干活，第 2 次
后台: 还在干活，第 3 次
后台: 还在干活，第 4 次
main: 我不想让它干了，可我没有办法通知它
后台: 还在干活，第 5 次
后台: 还在干活，第 6 次
后台: 还在干活，第 7 次
后台: 还在干活，第 8 次
main: 退出（后台任务被一起杀掉，不是它自己停的）
```

**问题在哪**：`main` 想让后台停，但**没有任何办法把"停"这个信号送过去**。只能整个进程退出——那是"连坐处死"，不是"通知下班"。

## 2.2 context 是什么

**`context.Context` 是一个接口**（不是结构体），它是个"**可以关闭的信号通道**"。

最小接口长这样（简化）：
```go
type Context interface {
	Done() <-chan struct{}               // 返回一个"只读的"通道
	Err() error                          // 为什么被取消
	Deadline() (time.Time, bool)         // 什么时候死
	Value(key any) any                   // 身上带的值
}
```

🔴 **`Done()` 返回的是 `<-chan struct{}`，不是 `chan struct{}`**（你今天闭卷答漏了这个 `<`）。
- `chan struct{}` = 可读可写
- `<-chan struct{}` = **只读**（箭头指着外面 = 只能从里面拿）
- 为什么只读？因为**只有 context 自己能关它**，使用方只能听。

**`cancel()` 干的事就是"关闭这个通道"**——所以所有在 `<-ctx.Done()` 上等着的 goroutine **同时醒来**。

## 2.3 三种造法

### ① `context.Background()` —— 根

```go
根 := context.Background()
```
- 它是**一切的起点**
- **本身不能被取消**（`Done()` 返回 `nil`、`Err()` 返回 `nil`、没有截止时间）
- 类比：**一块没有开关的电源板**。你插上去就有电，但它永远不会断电。

🔴 你问过"根为什么是 Background，是因为根就是这个吗"——**是的**，它就是"空实现"：所有方法都返回"啥也没有"。

### ② `context.WithCancel(父)` —— 手动停

```go
子ctx, 取消 := context.WithCancel(根)
```

返回**两个东西**：
- `子ctx`：派生的 context，**它比根多了一个"能被关掉"的能力**
- `取消`：一个函数，**调用它就等于"把子ctx 的 Done 通道关掉"**

```go
go func() {
	for {
		select {
		case <-子ctx.Done():        // 通道被关了
			fmt.Println("收到取消信号，我不干了")
			return
		default:                     // 没信号就继续
		}
		// 干活...
	}
}()

time.Sleep(2 * time.Second)
取消()                               // ← 通知它停
```

### ③ `context.WithTimeout(父, 时长)` —— 到点自动停

```go
子ctx, 取消 := context.WithTimeout(根, 3*time.Second)
```

- 3 秒后**自动**调 `取消()`
- 返回的 `取消` **仍然必须调**（早停就早释放，不等 3 秒）

🔴 **`go vet` 会抓你丢弃 cancel**：
```
main.go:10:7: the cancel function returned by context.WithTimeout should be called,
              not discarded, to avoid a context leak
```

⚠️ **`defer 取消()` 在 for 循环里不能用**——`defer` 会攒到函数返回时才执行，循环 100 次就攒 100 个 cancel 不调 → **泄漏**。必须手动调。

## 2.4 两个错误值，必须分清

| 错误值 | 含义 | 什么时候出现 |
|---|---|---|
| `context.DeadlineExceeded` | **时间到了** | `WithTimeout` 到期 |
| `context.Canceled` | **有人主动取消了** | 有人调了 `cancel()` |

**判断方式**：
```go
if 子ctx.Err() == context.DeadlineExceeded {
	// 超时
} else if 子ctx.Err() == context.Canceled {
	// 被主动取消
}
```

实跑（`3_超时取消.go`）：
```
[下载] 第 1 步做完了
[下载] 第 2 步做完了
[下载] 第 3 步前被取消：context deadline exceeded     ← 超时
慢任务返回: context deadline exceeded

外部: 不干了，cancel()
[上传] 第 2 步前被取消：context canceled              ← 主动取消
慢任务返回: context canceled
```

## 2.5 取消是"树形"的（🔴 重要）

```
        根
        │
    ┌───┴───┐
   子A      子B
```

**三条铁律**：
1. **取消子 A → 不影响兄弟 B**
2. **取消父 → 连带所有子（A、B 全停）**
3. `ctx.Err()` 全是 `context.Canceled`

实跑证据（`/tmp/tree/main.go`）：
```
[子A] 第 1 步
[子B] 第 1 步
[子A] 第 2 步
[子B] 第 2 步
[子A] 第 3 步
[子A取消()]              
[子A] 收到取消信号（context canceled），我停了
[子B] 第 4 步                                 ← 子B 继续跑
[子B] 第 5 步
[根取消()]                                   ← 取消根
[子B] 收到取消信号（context canceled），我停了
```

**为什么要树形**：一个 HTTP 请求进来 → 派生一堆子任务（查数据库、调下游）→ **请求被客户端断了，所有子任务必须一起停**，不能留下孤儿 goroutine。

## 2.6 `WithValue`：往下传值

```go
根 := context.Background()
父 := context.WithValue(根, "任务ID", 1)
子 := context.WithValue(父, "重试次数", 3)

子.Value("任务ID")     // 1     ← 子能看见父的
子.Value("重试次数")   // 3     ← 自己的
父.Value("重试次数")   // nil   ← 🔴 父看不见子的
```

**规则**：**只能往下传，不能往上取**。像继承——子类能拿到父类的，父类不知道子类加了什么。

**取不存在的 key 返回 `nil`，不报错** → 所以要用类型断言：
```go
if 任务ID, ok := ctx.Value("任务ID").(int); ok {
	fmt.Println("任务ID =", 任务ID)
}
```

### 🔴 string 当 key 会撞车（你今天的坑）

```go
根 := context.Background()
ctx1 := context.WithValue(根, "id", 100)   // 用户id
ctx2 := context.WithValue(ctx1, "id", 200) // 任务id

ctx2.Value("id")    // 200  ← 用户id 被静默覆盖了！
```

**不报错、不警告、就是覆盖了**——因为 Go 里 `"id" == "id"` 是同一个 key。

**正解：自定义类型**
```go
type 上下文键 string                       // ← 自定义类型

const 任务ID键 上下文键 = "任务ID"          // ← 用这个类型做 key

ctx3 := context.WithValue(根, 任务ID键, 7)
ctx3.Value(任务ID键)      // 7
ctx3.Value("任务ID")      // nil   ← 🔴 类型不同 = 不同的 key
```

**原理**：Go 的 map key 比较是"**类型 + 值**都得相等"。`上下文键("任务ID")` 和 `string("任务ID")` 是**不同类型**，所以不撞。

**为什么不用 int 做 key**：一样会撞（两个包都用 `1` 当 key 就撞了）。自定义类型是唯一干净的解。

## 2.7 `select` 里 `default` 决定"等"还是"看一眼"

```go
// 有 default：看一眼，没信号就往下走（非阻塞）
select {
case <-ctx.Done():
	return
default:
	// 继续干活
}

// 没有 default：阻塞等待，直到 ctx.Done() 有信号
select {
case <-ctx.Done():
	return
}
// ← 上面这个写法会让后台循环卡死在这里，永远不干活
```

**这是后台工人循环的命门**：写错了工人就卡在第一轮。

# 第三部分：net/http（下载器 v2 的基础）

## 3.1 最小的 HTTP 服务器（16 行）

```go
package main

import (
	"fmt"
	"net/http"
)

func 你好(w http.ResponseWriter, r *http.Request) {
	fmt.Fprint(w, "你好，我是服务器")
}

func main() {
	http.HandleFunc("/", 你好)
	fmt.Println("服务启动在 :8080")
	http.ListenAndServe(":8080", nil)
}
```

**三件套**：
1. `http.HandleFunc("/路径", 函数)` —— 注册路由
2. `func 名字(w http.ResponseWriter, r *http.Request)` —— 处理器签名（**固定，一个字符都不能变**）
3. `http.ListenAndServe(":端口", nil)` —— 开服务器

🔴 **你今天的错**：`import{` 写成花括号 → `missing import path` / `expected declaration, found "net/http"`。
**正解是圆括号 `import (`**。

## 3.2 `w` 和 `r` 是什么

| 参数 | 类型 | 干什么 |
|---|---|---|
| `w` | `http.ResponseWriter` | **往客户端写**（写 body、设 header、设状态码） |
| `r` | `*http.Request` | **从客户端读**（方法、URL、body、header） |

**记忆**：`w` = write（写回去），`r` = read（读进来）。

## 3.3 🔴 `ListenAndServe` 是阻塞的（你今天的大坑）

```go
func main() {
	...
	http.ListenAndServe(":8080", nil)   // ← 卡在这里，永远不返回

	// ↓↓↓ 这些代码一辈子不会执行 ↓↓↓
	go 后台工人(ctx)
}
```

**为什么**：`ListenAndServe` 开好服务器后就**死循环等请求**，它只在"端口被占"或"服务器崩了"时才返回。

**后果**（我实跑给你看了）：
```
=== 建任务 ===
{"id":1,"url":"a","状态":"已排队"}

=== 3 秒后查 ===
{"id":1,"url":"a","状态":"已排队"}      ← 永远不动

=== 服务日志 ===
服务启动在 :18112
=== 开始下载 出现次数 ===
0                                       ← 工人从没启动
```

**正确顺序**：
```go
func main() {
	// ① 先起后台
	根ctx, 根取消 := context.WithCancel(context.Background())
```

**常用状态码**：

|---|---|---|

### 🔴 中文字段名永远不被序列化（你今天的坑）

```go
type 任务 struct {
	网址  string     // ← 中文，永远不会出现在 JSON 里
	状态  string
	ID    int
}
```

实跑只返回：
```json
{"id":1}
```
**`网址` 和 `状态` 静默消失了**，编译器一句都不提示。

**根因**：`encoding/json` 用 **`unicode.IsUpper(第一个字符)`** 判断"字段是不是导出的"。中文的 `IsUpper` 返回 `false` → 被当成**未导出字段** → 跳过。

**正解：英文字段名 + tag 保留中文**
```go
type 任务 struct {
	ID     int    `json:"id"`
	URL    string `json:"url"`
	Status string `json:"状态"`      // ← tag 是"给 JSON 用另一个名字"
}
```

实跑：`{"id":1,"url":"http://example.com/a.txt","状态":"已排队"}` ✅

## 3.7 `map` 存指针才能改到原对象

## 4.4 🔴 后台工人（这一段最重要）

```go
func 后台工人(ctx context.Context) {
	for {
		// ① 每轮先看"该不该下班"
		select {
		case <-ctx.Done():
			fmt.Println("后台工人：收到停止信号，下班")
			return
		default:                     // ← 没有它就会阻塞卡死
		}

		// ② 找活（加锁）
		任务表锁.Lock()
		var 要做的 *任务
		for _, t := range 任务表 {
			if t.Status == "已排队" {
				要做的 = t
				break
			}
		}
		// 找到就"立刻"标记成"下载中"——防别人抢
		if 要做的 != nil {
			要做的.Status = "下载中"
		}
		任务表锁.Unlock()

		// ③ 没活干就歇一会（不加会烧 CPU）
		if 要做的 == nil {
			time.Sleep(200 * time.Millisecond)
			continue
		}

		// ④ 干活（这时候不能持锁！）
		...
	}
}
```

**四个关键点**：

| # | 点 | 为什么 |
|---|---|---|
| 1 | `select` + `default` | 非阻塞检查；没 default 会阻塞卡死 |
| 2 | **找到立刻改"下载中"** | 否则下一轮又找到它，重复干活 |
| 3 | 没活干必须 `Sleep` | 否则死循环把 CPU 一个核跑满 |
| 4 | **干活时不持锁** | 否则 `/status` 请求全卡住（2 秒下载期间谁都查不了） |

## 4.5 🔴 真下载 + 3 秒超时（5C）

```go
// ① 给这个任务造一个 3 秒超时的子 ctx
子ctx, 子取消 := context.WithTimeout(ctx, 3*time.Second)

// ② 用子 ctx 造请求（根取消时这里也会被中断）
req, err := http.NewRequestWithContext(子ctx, "GET", 要做的.URL, nil)
if err != nil {
	子取消()
	// 标记"失败"
	continue
}

// ③ 发请求
resp, err := http.DefaultClient.Do(req)

// ④ 三种结果
任务表锁.Lock()
if err != nil {
	if 子ctx.Err() == context.DeadlineExceeded {
		要做的.Status = "超时"
	} else {
		要做的.Status = "失败"
	}
} else {
	io.Copy(io.Discard, resp.Body)      // 🔴 必须读走
	resp.Body.Close()                   // 🔴 必须关
	要做的.Status = "已完成"
}
任务表锁.Unlock()
子取消()                                // 🔴 手动调，不能用 defer
```

**五个要点**：

1. **`context.WithTimeout(ctx, 3*time.Second)`** 继承根 ctx：根取消 → 这里也取消 → 请求中止
2. **`io.Copy(io.Discard, resp.Body)`**：不读完 body，**连接不会释放**，连接池会泄漏
3. **`resp.Body.Close()`**：必须关
4. **`子ctx.Err() == context.DeadlineExceeded`**：区分"超时"和"别的错"
5. **`子取消()` 手动调**：`defer` 在 for 循环里会攒到最后

🔴 **你第一次只写了 2 行**：
```go
req, _ := http.NewRequestWithContext(子ctx, "GET", 要做的.URL, nil)  // 子ctx 从没定义
resp, err := http.DefaultClient.Do(req)                             // resp/err 声明了没用
```
三个问题：① `子ctx` 不存在（应先造）② `resp`/`err` 没用（Go 报错）③ 状态不分成功失败。
