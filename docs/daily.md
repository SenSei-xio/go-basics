## 2026-11-04（周三 · W4 第 3 天）

### 学到

1. **协议头拆包**：`header := 0x1F2E0105` —— 高 16 位是魔数、低 16 位是包长。
   - 打包：`魔数期望<<16 | 包长`（`<<` 把魔数抬到高位，`|` 把包长塞进空位）
   - 取魔数：`header>>16 & 0xFFFF`（先挪再筛）
   - 取包长：`header & 0xFFFF`（本来就在低位，直接筛）
   - 校验：`header>>16&0xFFFF == 魔数期望`
2. **`>>` 是「搬位置」不是「算数」**：整排 32 格往右挪 16 格，右边挤出去的扔掉、左边补 0。

1. **`context` 不是"传信号"，是"传一条可以被关闭的通道"**：`ctx.Done()` 返回 `<-chan struct{}`（只读单向），`cancel()` 干的事就是**关闭这个通道**，所以所有 `<-ctx.Done()` 同时醒来。
2. **三种造法各有用途**：
   - `context.Background()` —— 根，**本身不能取消**（`Done()` 返回 nil、`Err()` 返回 nil）只当起点
   - `context.WithCancel(父)` —— 手动停，返回 `(ctx, cancel)`
   - `context.WithTimeout(父, 时长)` —— 到点自动停，返回 `(ctx, cancel)`，**cancel 仍然必须调**（`go vet` 会抓你丢弃它：`the cancel function returned by context.WithTimeout should be called, not discarded, to avoid a context leak`）
3. **两条错误值的区别**：`context.DeadlineExceeded` = 时间到了；`context.Canceled` = 有人主动 cancel。**判断用 `ctx.Err()`**。
4. **取消是树形的**：取消子不影响兄弟，**取消父连带所有子**。实跑验证：取消子A 后子B 继续跑到第 5 步；取消根后子B 也停。
5. **`WithValue` 只能往下传，不能往上**：子能看见父的值，父看不见子的。取不存在的 key 返回 `nil` 不报错，所以要用 `v, ok := ctx.Value(k).(int)`。
6. **用 string 当 key 会撞车**：两处都写 `"id"`，后写的静默覆盖前面的，**不报错**。正解是自定义类型 `type 上下文键 string` + `const 任务ID键 上下文键 = "任务ID"`——Go 里类型不同就是不同 key。
7. **`select` 里 `default` 决定"等"还是"看一眼"**：`select { case <-ctx.Done(): return; default: }` 是**非阻塞检查**；去掉 `default` 就变成阻塞等待，后台循环会卡死。
8. **net/http 最小的三件套**：`http.HandleFunc("/路径", 函数)` + `func 函数(w http.ResponseWriter, r *http.Request)` + `http.ListenAndServe(":端口", nil)`。
9. **`ListenAndServe` 是阻塞调用，永远不返回**：所以它后面的代码**一辈子不执行**——`go 后台工人()` 必须写在它**前面**。
10. **每个接口的"输入从哪来"不一样**：`/download` 和 `/cancel` 从 body JSON（`json.NewDecoder(r.Body).Decode(&请求)`），`/status` 从 URL 查询串（`r.URL.Query().Get("id")` + `strconv.Atoi`）。**复制粘贴前先问输入从哪来**。
11. **中文字段名永远不被 JSON 序列化，而且不报错**：`encoding/json` 用 `unicode.IsUpper` 判断导出，中文 `IsUpper=false` → 静默丢掉。必须英文字段名 + tag 保留中文（`ID int \`json:"id"\`` / `Status string \`json:"状态"\``）。
12. **`map[int]*任务` 存指针才能改到原对象**：存值的话 `任务表[id].Status = "已取消"` 编译不过（map 元素不可寻址）。
13. **加锁的三条铁律**（下载器里练出来的）：① 找活 + 标记"我来做"必须在**同一把锁**里 ② **干活时不持锁**（否则 `/status` 全卡） ③ 改结果时再拿一次锁。
14. **超时下载的完整写法**：`子ctx, 子取消 := context.WithTimeout(ctx, 3*time.Second)` → `http.NewRequestWithContext(子ctx, "GET", url, nil)` → `http.DefaultClient.Do(req)` → `io.Copy(io.Discard, resp.Body)` + `resp.Body.Close()` → 用 `子ctx.Err() == context.DeadlineExceeded` 区分超时。**`defer 子取消()` 在 for 循环里不能用**（会攒到最后），必须手动调。
15. **不读走 body 连接不释放**：`io.Copy(io.Discard, resp.Body)` 是必须的，否则连接池泄漏。

### 学到

1. **`去重` 为什么用 `map[int]*任务` 而不是 `map[int]任务`** —— 存值改的是副本，原件不变；存指针一步改到。实跑：`map[int]任务` 改完表里仍「已排队」，必须 `任务表[id] = t` 放回去
2. **Mutex 是「门」不是「变量旁边的标签」** —— `Lock()` 敲门排队、只有拿到锁的能进、`Unlock()` 放人进来。无锁两 goroutine 改同一个字段 → `-race` 报 `WARNING: DATA RACE` / `Write at 0x00c00009c030 by goroutine 10`
3. **Method 检查是第一道门** —— 删掉它有两种后果：① GET 无 body → `Decode 报错: EOF`，用户拿到「请求格式不对」（**报错骗人**）② GET 带 JSON body → `Decode err = <nil>`，**GET 也能创建资源**（爬虫/预加载会乱建）
4. **`defer 任务表锁.Unlock()` 必写在 `Lock()` 下一行** —— 手动 Unlock 三个坑：中间有 `return` 就漏 / panic 漏 / 改代码忘。`defer` 免疫三个
5. **GET 用 URL 带参数（`?id=1`），POST 用 body 带参数（`{"id":1}`）** —— GET 的 body 是空的（`io.ReadAll` → `""`），改成从 body 读 JSON 就永远读不到 id
6. **锁只包读写共享数据那几行** —— 实测持锁 3 秒 → `/status` 等 **2.9 秒**；不持锁 → **0 秒**。超过 1 毫秒的操作都不该待在锁里
7. **`err` 看「通不通」，`StatusCode` 看「成不成」，两个都过才算真成功** —— 请求 404 地址时 `err = <nil>` / `resp.StatusCode = 404`
8. **`ListenAndServe` 会阻塞，写在它后面的代码永远不执行** —— 实跑：把 `go 后台工人` 写后面 → 编译过、POST 正常、查状态**永远「已排队」**、日志 `开始下载` **0 次**（静默失败，同类坑第 2 次）
9. **`select + default` 的 `default` 不能省** —— 省了 channel 满时 `select` 一直阻塞，整个 HTTP 请求卡死
10. **ctx 不需要加锁** —— 读的不用锁、写的要锁；`cancel()` 是 `close(通道)` 不是改内容，close 并发安全且关闭后所有 `<-ch` 立刻返回
11. **`map` vs 切片的量级差** —— 实跑 10 万任务查 10 万次：切片 **1.98 秒** vs map **1.45 毫秒**，**慢 1370 倍**
12. **有「状态表」的系统用轮询，只有「消息流」的系统才用 channel** —— 留 channel 会变两份真相；HTTP handler 里发通道满会阻塞请求
13. **超时的三条约束** —— 大于正常耗时（不误杀）+ 小于用户忍耐（不干等）+ 业界 3~10 秒。实测服务器每次 1 秒：超时 300ms → 超时误杀；3s / 30s → 成功 1.001s

### 学到

1. **三次握手状态表**：客户端 `CLOSED → SYN_SENT → ESTABLISHED`；服务器 `LISTEN → SYN_RCVD → ESTABLISHED`。**客户端发完第③步就进，服务器收到第③步才进**（早半个瞬间）
2. **四次挥手状态表**：主动方 `ESTABLISHED → FIN_WAIT_1 → FIN_WAIT_2 → TIME_WAIT → CLOSED`；被动方 `ESTABLISHED → CLOSE_WAIT → LAST_ACK → CLOSED`
3. **`SYN_SENT` = 已发出在等回应**，不是「没发出去」。能在 netstat 里看到就说明包已经发出去了
4. **`TIME_WAIT` 永远属于先动手的一方**。谁先 Close，谁等 2MSL（Windows 约 4 分钟）
5. **`TIME_WAIT` 挡的是客户端本地端口**，不是服务端。实测：客户端固定端口连 40 次 → 成功 5 失败 35；服务端堆 12 条 TIME_WAIT → 新连接照样成功 `err = <nil>`
6. **`CLOSE_WAIT` 是 bug**：对方发了 FIN，你代码里没 `Close()`，会泄漏文件描述符
7. **`TIME_WAIT` 两个理由**：①怕最后 ACK 丢（对方重发 FIN，还在 `TIME_WAIT` 就认得，否则回 RST）②让旧包过期（同四元组复用会被误收）
8. **握手三次挥手四次的原因**：握手时双方手里都空着，SYN 和 ACK 能合并；挥手时一方可能还有数据没发完。**两次不够**是因为防不住延迟的旧 SYN（半开连接）
9. **155 最小栈**：两个栈联动。**Push 时跟「当前最小值」比**（`<=` 才压），**Pop 时跟「当前最小值」比**（`==` 才弹）
10. **Go 里栈就是切片**：`append` 入、`[len-1]` 看、`[:len-1]` 弹。**三种写法区别**：`s.数据`（整个）、`s.数据[len-1]`（一个元素）、`s.数据 = s.数据[:len-1]`（变短）

2. **`:=` vs `=` 第三次错** —— `s.最小值 := ...` 应为 `s.最小值 = ...`（`:=` 左边必须是新变量名）
3. **「取值」和「弹掉」分不清** —— `顶 := s.最小值[len-1]` 是取值（切片没变），`s.最小值 = s.最小值[:len-1]` 才是弹掉

### 学到的

1. **`conn.Close()` = 关门**，不是「链接」——链接（connect）是 `net.Dial` 干的事
2. **`defer` 必须用在收尾** —— `return` 会截胡写在函数最后一行的收尾代码
3. **`TIME_WAIT` 两个理由**：①怕自己发的最后一个 ACK 丢 ②让旧包在网络上过期
4. **`TIME_WAIT` 堵的是客户端本地端口**（服务端监听端口不受影响）
5. **五字诀「换」放循环里 = 提前刹车**：第 1 轮后 `list = 新list` 让 `len(list)` 从 4 变 1，第 2 轮 `1 < 1` 不成立直接退出
6. **`io.Writer` 的 n = 实际写进底层设备的字节数**（第 4 次考）
7. **`io.Copy` 的 `short write`**：`Write` 返回 `0, nil` =「写了 0 字节且一切正常」，`io.Copy` 判定说谎 → 自己造一个 `short write`
8. **同义反复判断 = 漏了真正要比较的变量**（`len(栈) == len(栈)`）；编译器和 `go vet` 都不报，只有测试能抓
9. **`io.EOF` 三种情况要分清**：对端不说话 → 阻塞（加 deadline 才返回 `i/o timeout`）；对端发数据后关 → 第一次 `n=5 err=<nil>`，再读才 `n=0 err=EOF`；对端不发就关 → 直接 `n=0 err=EOF`
10. **树的遍历换一棵树还能全对** —— 不是背答案
11. **★「空在哪个函数里，答案就不可能是那个函数自己」** —— 232 五个空里四个能被这条当场抓出来（唯一例外：调另一个已实现的方法，如 `Pop` 里调 `q.倒一下()`）
12. **★ 缩进是 Go 唯一的结构线索** —— 挖空时「空下面所有代码都比我多缩进一层」= 这一行必须打开一个块（`for {` / `if ... {` / `func ... {`）。第一次填读写循环错 3 个，根因是我把缩进做成平的
13. **★ 递归三行式**：① 最小情况返回什么（`n == nil → 0`）② 子问题怎么调自己（`最大深度(n.Left)`）③ 怎么合并（`1 + max(左边, 右边)`）
14. **★ 原地改结构 vs 返回一个数**：104 是 `x := 递归(...)`（要一个数）；226 是直接调 `翻转(n.Left)` 不接返回值（原地把指针换掉）
