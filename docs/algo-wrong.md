## 002 · 20. 有效的括号（2026-11-16）

**难度**：简单 · **状态**：`✅ 通过（第 2 次改对，8/8）`

### 一、第一次写（挖空版 5 个空，错 2 个）

| 空 | 我写的 | 正确 | 性质 |
|---|---|---|---|
| 空 1 | `[]rune{}` | `[]rune{}` | ✅ |
| 空 2 | `字符` | `字符` | ✅ |
| **空 3** | `len(栈) == len(栈)` | `len(栈) == 0` | ❌ **同义反复** |
| **空 4** | `'(' == '('` | `栈顶 == '('` | ❌ **常量跟常量比** |
| 空 5 | `len(栈) == 0` | `len(栈) == 0` | ✅ |

- 跑出来 `通过 5 / 8`，`"()"` `"()[]{}"` `"{[]}"` 三个全挂
- `go vet` **一个字都没报** —— 这类错编译器查不出来，只有测试能抓

### 二、根因（同一个病，两种表现）

**写判断条件时，把「真正要比较的那个变量」漏掉了。**

```go
if len(栈) == len(栈)          // ← 只有一样东西，自己跟自己比，恒 true
配对 := ('(' == '(' && ...)     // ← 两边都是死常量，恒 true
```

**这两个条件永远为真**，所以：
- 空 3 错 → 一遇到第一个右括号就 `return false`，`"()"` 第 2 个字符就挂
- 空 4 错 → 第一个条件退化成「只要字符是 `)` 就算配上」，栈顶是什么不管了

### 三、正确解（背这个）

```go
func 有效括号(s string) bool {
	栈 := []rune{}
	for _, 字符 := range s {
		switch 字符 {
		case '(', '[', '{':
			栈 = append(栈, 字符)          // 左括号 → 记账
		case ')', ']', '}':
			if len(栈) == 0 {              // ① 账本是空的，这个右括号没人配
				return false
			}
			栈顶 := 栈[len(栈)-1]
			配对 := (栈顶 == '(' && 字符 == ')') ||
				(栈顶 == '[' && 字符 == ']') ||
				(栈顶 == '{' && 字符 == '}')
			if !配对 {                     // ② 类型对不上
				return false
			}
			栈 = 栈[:len(栈)-1]            // ③ 销账（必须有 = 号）
		}
	}
	return len(栈) == 0                    // ④ 账本空 = 全部关完
}
```

**四步口诀：记账 → 查空 → 对型 → 销账；最后看账本空不空。**

### 四、为什么用栈

括号的天然规则是「**最近打开的最先关闭**」= 后进先出 = 栈。

反例证明不能用「数数」：`")("` 左右各一个、数量相等，但右括号在前 → 无效。
`"([)]"` 也是各两个，但 `(` 还没关就被 `]` 关了 → 无效。
**光数数量不知道「谁应该先关」，必须记顺序。**

### 五、踩过的坑（三个）

1. **栈空了还遇到右括号** → `栈[len(栈)-1]` 会 `index out of range`，必须先判 `len(栈) == 0`
2. **`栈[:len(栈)-1]` 少了 `=`** → 只是个视图，切片没变短，等于没弹（155 最小栈栽过同一个坑）
3. **最后忘了判空** → `"("` 只有左括号，循环走完栈里还剩 `(`，必须 `return len(栈) == 0`

### 六、下次复习要点（一句话）

> 有效括号 = **一个栈 + 三次判断**。遇到左括号压栈；遇到右括号先看栈空不空，再看栈顶配不配，配就弹；最后看栈空不空。**判断条件里必须有「栈顶」这个变量，否则就是在自己跟自己比。**

## 001 · 155 最小栈（LeetCode 155）⚠️

**日期**：2026-11-15 23:50
**状态**：✅ 通过（实跑 `最小值 = 3 / 3 / 5`、`栈顶 = 5`）
**用时**：16:30 → 23:50（中间有 6 小时空窗，实际约 50 分钟）

### 题目
设计一个栈，支持 `Push` / `Pop` / `Top`，**并且能在 O(1) 时间返回最小值 `GetMin`**。

### 我错在哪（4 处）

**错误 1 · `Push` 压错了对象**
```go
最小栈 = append(最小栈, x)      // ❌
```
```
.\main.go:18:22: 最小栈 (type) is not an expression
```
`最小栈` 是**类型名（图纸）**，不是变量。要压的是**这个实例的字段**。
```go
s.最小值 = append(s.最小值, x)   // ✅
```

**错误 2 · `Pop` 把「取值」当成了「弹掉」**
```go
顶 := s.最小值[len(s.最小值)-1]        // ❌ 这是取值，切片没变
s.最小值 = s.最小值[:len(s.最小值)-1]    // ✅ 这才是弹掉
```
**三种写法必须分清：**

| 想要 | 写法 | 切片的长度变了吗 |
|---|---|---|
| 整个切片 | `s.最小值` | — |
| 取切片里的一个元素 | `s.最小值[len(s.最小值)-1]` | 没变 |
| 弹掉最后一个（切片变短） | `s.最小值 = s.最小值[:len(s.最小值)-1]` | **变了** |

**错误 3 · `Top` 用了别的函数的局部变量**
```go
func (s *最小栈) Top() int {
    return 顶                           // ❌ undefined: 顶
}
```
`顶` 是 `Pop` 里的局部变量，**只活在那一个函数里**。`Top` 要自己取：
```go
return s.数据[len(s.数据)-1]           // ✅
```

**错误 4 · `GetMin` 返回了整个切片**
```go
return s.最小值                         // ❌ cannot use s.最小值 ([]int) as int
return s.最小值[len(s.最小值)-1]         // ✅
```

**错误 5 · `:=` 用在了已存在的字段上**
```go
s.最小值 := s.最小值[:len(s.最小值)-1]   // ❌ non-name s.最小值 on left side of :=
s.最小值 = s.最小值[:len(s.最小值)-1]    // ✅
```
**规则**：`:=` 左边必须是**新变量名**；`s.字段` 早就存在了，只能用 `=`。
> 这个知识点 **11-03 起锚考过、11-12 状态体检错过、今天第三次遇到**。

### 正确思路（两条规则）

**规则 1 · Push**：新值 `<=` **当前最小值**（不是栈顶！）→ 最小值栈也压
```go
s.数据 = append(s.数据, x)
if len(s.最小值) == 0 || x <= s.最小值[len(s.最小值)-1] {
    s.最小值 = append(s.最小值, x)
}
```

**规则 2 · Pop**：弹出的值 `==` **当前最小值** → 最小值栈也弹
```go
顶 := s.数据[len(s.数据)-1]
s.数据 = s.数据[:len(s.数据)-1]
if 顶 == s.最小值[len(s.最小值)-1] {
    s.最小值 = s.最小值[:len(s.最小值)-1]
}
```

**为什么用 `<=` 不用 `<`**：有重复值时必须都记录，否则 pop 掉一个后最小值栈会空。

### 为什么会错
1. **不知道 `[]int` 和 `int` 在返回值上的区别** —— 这个属于 Go 基础，不是算法问题
2. **`:=` vs `=` 第三次错** —— 这是**反复出错点**，已进 `mastery.md`
3. **「栈 == 切片」这个映射不熟** —— 知道概念（LIFO）但不知道用 append 和切片语法实现

### 下次复习要点（面试前看这一条就够）
> 最小栈 = 两个栈。**Push 时跟「当前最小值」比，Pop 时跟「当前最小值」比。** 两次比较，两行 if。其余全是栈的基本操作：`append` 入、`[len-1]` 看、`[:len-1]` 弹。

## 003 · 232 用栈实现队列（2026-11-18）

**难度**：简单 ｜ **分类**：栈 / 队列 ｜ **状态**：✅ 通过（第一版错，第二版对）

### 题目
只许用两个栈（切片）实现队列的 `Push` / `Pop` / `Peek` / `Empty` 四个操作，要求先进先出。

### 错在哪 —— 五个空，四个填成了「自己调自己」

| 空 | 第一版填的 | 正确 | 错因 |
|---|---|---|---|
| 空1（Push 里） | `q.Push(x)` | `append(q.进栈, x)` | 在 Push 里调 Push = 无限递归 |
| 空2（倒一下 开头） | `q.Pop()` | `len(q.出栈) > 0` | Pop 返回 int，不能当 if 条件 |
| 空3（倒一下 循环里） | `q.Peek()` | `q.进栈[len(q.进栈)-1]` | Peek 内部会调「倒一下」，绕回去 |
| 空4（Pop 第一行） | `q.Pop()` | `q.倒一下()` | 自己调自己 |
| 空5（Empty） | `q.Empty()` | `len(q.进栈) == 0 && len(q.出栈) == 0` | 自己调自己 |

**编译器报错原文**：
```
.\2_挖空练习.go:37:13: q.Push(x) (no value) used as value
.\2_挖空练习.go:43:5: non-boolean condition in if statement
```

### 根因（这是今天最值钱的一条）
**把「函数名 → 中文」的伪代码当成了答案模板**，于是按「这个空在哪个函数里 → 填那个函数名」去填。

正确的心智顺序应该是：
1. **先问「这一行缺什么动作」**（加进去？判断空？取栈顶？）
2. **再问「Go 里这个动作叫什么」**（append？len？`[len-1]`？）

**硬规则（可当场自查）**：
> 空在哪个函数里，答案就不可能是那个函数自己。
> 唯一例外：空4 在 `Pop` 里却填 `q.倒一下()` —— 因为那是**另一个**函数。

### 正确解

```go
func (q *队列) Push(x int) {
	q.进栈 = append(q.进栈, x)
}

func (q *队列) 倒一下() {
	if len(q.出栈) > 0 {
		return
	}
	for len(q.进栈) > 0 {
		顶 := q.进栈[len(q.进栈)-1]
		q.进栈 = q.进栈[:len(q.进栈)-1]
		q.出栈 = append(q.出栈, 顶)
	}
}

func (q *队列) Pop() int {
	q.倒一下()
	顶 := q.出栈[len(q.出栈)-1]
	q.出栈 = q.出栈[:len(q.出栈)-1]
	return 顶
}

func (q *队列) Empty() bool {
	return len(q.进栈) == 0 && len(q.出栈) == 0
}
```

### 一句话复习要点（面试前看这条）
> **两个栈，一个收一个放。要取的时候把「收的」全部倒进「放的」，顺序就反过来了。出栈非空时坚决不能倒 —— 这是唯一陷阱。**

### 复杂度
- 时间：`Push` O(1)；`Pop`/`Peek` **均摊 O(1)**（每个元素最多被倒一次、被弹一次）
- 空间：O(n)

### 验证记录
- `go run 2_挖空练习.go` → **16 / 16 通过 🎉**
- `go vet` 干净 / `gofmt -l .` 干净
- 关键测试通过：`Push(30) 后 Pop 得 20 不是 30`（证明「出栈非空不倒」写对了）

## 005 · 226. 翻转二叉树（2026-11-18）

**难度**：简单 · **状态**：`✅ 通过（一次全过，5/5 空 + 6/6 测试）`

### 一、题目

```
      4
    /   \
   2     7
  / \   / \
 1   3 6   9
```
翻转成：
```
      4
    /   \
   7     2
  / \   / \
 9   6 3   1
```

### 二、正确解

```go
func 翻转(n *TreeNode) *TreeNode {
	if n == nil {
		return nil
	}
	翻转(n.Left)                           // ① 先把左子树翻好（原地改，不用接返回值）
	翻转(n.Right)                          // ② 再把右子树翻好
	n.Left, n.Right = n.Right, n.Left      // ③ 最后交换自己的两个孩子（同时赋值）
	return n                               // ④ 返回自己
}
```

### 三、最容易错的三个点

| 坑 | 错法 | 为什么错 |
|---|---|---|
| **① 只换根** | 只写 `n.Left, n.Right = n.Right, n.Left` | 孩子那几棵子树还是原样，必须递归下去 |
| **② 接了返回值** | `n.Left = 翻转(n.Left)` | 能跑，但多此一举 —— `翻转` 是**原地改**，`n.Left` 本来就已经被改好了 |
| **③ 用 `:=`** | `n.Left, n.Right := n.Right, n.Left` | `n.Left` / `n.Right` 是已存在的字段，`:=` 是「声明新变量」，会报 `no new variables on left side of :=` |

### 四、为什么「先递归还是先交换」都对

两种写法结果完全相同：
- 先递归再交换（本解的写法）
- 先交换再递归（交换后左右子树名字对调了，但递归下去还是把两边都翻，结果一样）

**唯一不能省的是「先判 `n == nil`」** —— 不判就会空指针崩。

### 五、这一题考的是什么

考的不是「会不会写递归」，是**「知不知道什么时候不需要接返回值」**：

| 题 | 递归的产物 | 怎么写 |
|---|---|---|
| **104 最大深度** | 一个**数**（深度） | `左边 := 最大深度(n.Left)` ← 必须接 |
| **226 翻转二叉树** | **结构被改了**（副作用） | `翻转(n.Left)` ← 不用接 |

**一句话判断法**：递归函数返回的东西是「答案」还是「同一个对象」？
- 答案是数/字符串 → 接住它
- 同一个对象（原地改了）→ 不用接

### 六、一句话复习要点（面试前看这条）
> **先判空 → 翻左 → 翻右 → 交换自己 → 返回自己。** 递归改结构的题不接返回值，因为结构已经改了。

### 七、验证记录
- `go run 2_挖空练习.go` → **6/6 全过**（空树 / 单节点 / 题目那棵 / 只有左链 / 只有右链 / 左右各一个叶子）
- `go vet` 干净 / `gofmt -l .` 干净
- 5 个空**一次全对**，含 `n.Left, n.Right = n.Right, n.Left` 这个同时赋值语法

## 004 · 104. 二叉树的最大深度（2026-11-18）

**难度**：简单 · **状态**：`⚠️ 会但写错（4 空错 1：漏 if，补上后 6/6 全过）`

### 一、题目

求一棵二叉树的最大深度。深度 = 从根到最远叶子经过的**节点个数**（根单独一个节点算深度 1）。

### 二、我错在哪

```go
	n == nil {          // ← 错：少了 if
		return 0
	}
```

**编译器报错原文（两行，第二行极具误导性）**：
```
.\3_挖空练习.go:37:3: syntax error: unexpected keyword return, expected expression
.\3_挖空练习.go:40:2: syntax error: non-declaration statement outside function body
```

第二行说「第 40 行的声明语句在函数体外面」，**听起来像括号不配对**，其实是第 36 行少 `if`，编译器以为**函数到那儿就结束了**，后面全是「函数外」。→ **报错行号可能离真正出错的地方很远。**

### 三、正确解

```go
func 最大深度(n *TreeNode) int {
	if n == nil {
		return 0
	}
	左边 := 最大深度(n.Left)
	右边 := 最大深度(n.Right)
	return 1 + max(左边, 右边)
}
```

### 四、递归三行式（这一题是范本）

1. **最小情况返回什么** → `n == nil` 时返回 `0`（一个节点都没有，深度是 0）
2. **子问题怎么调自己** → `最大深度(n.Left)` / `最大深度(n.Right)`
3. **怎么合并** → `1 + max(左边, 右边)`，那个 `1` 是「自己这一层」

**逐层展开验证**（题目那棵树 `3/9/20/15/7`）：
```
3 的深度 = 1 + max(9 的深度=1, 20 的深度=2) = 1 + 2 = 3
20 的深度 = 1 + max(15 的深度=1, 7 的深度=1) = 1 + 1 = 2
15 的深度 = 1 + max(nil=0, nil=0) = 1 + 0 = 1
nil 的深度 = 0    ← 停
```

### 五、一句话复习要点
> **空树 0，否则 1 + max(左, 右)。那个 1 是「自己」。** `if` 不能省，中文说「如果」Go 里必须有 `if`。

### 六、验证记录
- 只补一个 `if` 字，其它一字未动 → **6/6 全过**
- `go vet` 干净 / `gofmt -l .` 干净

## 006 · 协议头 pack / unpack（2026-11-22 · 非 LeetCode，但面试要手写）

### 一、题目
设计一个协议头（魔数 4 + 版本 2 + 长度 4 = 10 字节），写 `pack` 把正文打包成帧，写 `unpack` 从帧里切出正文。

### 二、错在哪
1. 空 3 写 `帧[7:10]` —— 只有 3 格，`PutUint32` 要 **4 格**
   → `panic: runtime error: index out of range [3] with length 3`（`4_挖空练习.go:46`）
2. 保留了 `_ = binary.BigEndian.PutUint32(...)` 的 `_ =`
   → `binary.BigEndian.PutUint32(帧[0:4], 魔数) (no value) used as value`
3. 顺序错：把 `copy(帧[头长度:], 正文)` 写在最上面

### 三、正确解（背这个）

```go
const 头长度 = 10

func pack(正文 []byte) []byte {
    帧 := make([]byte, 头长度+len(正文))
    binary.BigEndian.PutUint32(帧[0:4], 0x47414D45)          // 魔数 "GAME"
    binary.BigEndian.PutUint16(帧[4:6], 0x0001)              // 版本
    binary.BigEndian.PutUint32(帧[6:10], uint32(len(正文)))  // 长度
    copy(帧[头长度:], 正文)                                   // 正文最后放
    return 帧
}

func unpack(帧 []byte) ([]byte, error) {
    if len(帧) < 头长度 {
        return nil, fmt.Errorf("帧太短")
    }
    if binary.BigEndian.Uint32(帧[0:4]) != 0x47414D45 {   // 先校验魔数
        return nil, fmt.Errorf("魔数不对：0x%X", binary.BigEndian.Uint32(帧[0:4]))
    }
    长度 := binary.BigEndian.Uint32(帧[6:10])             // 再读长度
    if len(帧) < 头长度+int(长度) {
        return nil, fmt.Errorf("正文不全")
    }
    return 帧[头长度 : 头长度+int(长度)], nil
}
```

### 四、为什么这么设计
- **魔数**：用来识别「这确实是我的协议的帧」，防止读到别的协议的数据
- **长度前缀**：TCP 是字节流没有边界，只能靠长度自己数
- **统一大端**：跨平台一致；小端读 300 会读成 **738,263,040**（741 万倍）

### 五、踩过的坑
1. **`Put*` 系列没有返回值**，`Uint*` 系列有返回值
2. **`帧[a:b]` 是 b−a 格**，`uint32` 必须 4 格
3. **魔数校验必须在读长度之前** —— 顺序反了会拿垃圾数据当长度越界
4. **正文必须最后放** —— 先放正文再放头会覆盖正文

### 六、下次复习要点（一句话）
**`Put` 没返回值、`帧[a:b]` 有 b−a 格、先验魔数再读长度、正文最后 copy。**

### 三、正确解（四段完整代码）

**① echo 六动作（默写用）**
```go
ln, err := net.Listen("tcp", "127.0.0.1:19200")   // 开门
if err != nil { fmt.Println("监听失败", err); return }
defer ln.Close()
for {
    conn, err := ln.Accept()                       // 等
    if err != nil { return }
    go 处理客人(conn)                               // 交给协程
}
// 客人那边：
for {
    n, err := conn.Read(buf)                       // 读
    if err != nil { return }                       // 判
    conn.Write(buf[:n])                            // 发回去
}
```

**② 广播（跳过发送者）**
```go
func (t *连接表) 广播(发送者 net.Conn, 内容 []byte) {
    合影 := t.快照()
    for conn := range 合影 {
        if conn == 发送者 { continue }   // ← 唯一区别
        conn.Write(内容)
    }
}
```

**③ 心跳**
```go
for {
    conn.SetReadDeadline(time.Now().Add(15 * time.Second))   // 每次 Read 前重设
    n, err := conn.Read(buf)
    if err != nil {
        ne, ok := err.(net.Error)
        if ok && ne.Timeout() { fmt.Println("对方假死,踢掉") }
        return
    }
    if string(buf[:n]) == "ping\n" {
        conn.Write([]byte("pong\n"))
        continue                          // 心跳不广播
    }
}
```

**④ 断线广播**
```go
func 处理客人(conn net.Conn) {
    名字 := conn.RemoteAddr().String()
    defer 表.广播所有人([]byte(名字 + " 下线了\n"))   // 后登记 → 先执行的是下面那行
    defer conn.Close()
}
```

### 四、为什么这么设计

**为什么广播要 `for`**：TCP 是**点对点**，一个 `conn` 只代表一个客人。要发给 5 个人，只能 `Write` 5 次。没有「全员广播」这种能力——这是应用层自己实现的。

**为什么每次 Read 前都要重设 deadline**：`SetReadDeadline` 设的是**这一次**的系统调用超时。它不会自动续期。设一次 = 只管一次 Read。不重设 = 第二次 Read 又变成无限等待。

**为什么超时 = 3 × 心跳间隔**：允许丢 2 个心跳不误判。如果超时=心跳间隔，那「心跳晚到 1 毫秒」就误杀。

**为什么 `defer` 顺序是「先关闭再广播」**：后进先出。先 `defer 广播`、后 `defer Close` → `Close` 先执行。这个顺序正好对：先断开，再告诉别人「他断开了」。

### 五、踩过的坑（一句话版）
1. **`conn.Write(值)` 不放类型**
2. **`for` 外没有 `conn`**
3. **少一个 `}` 报错会指到 `main`**
4. **字符串拼接空格要自己加**
5. **改完先 `Ctrl+S` 再回话**
6. **`go run` 的残留进程会占端口**

### 六、下次复习要点（一句话）
**开门→等→交给协程；他那边读→判→发回去；发之前先拍合影；每次 Read 前重设 15 秒；`defer` 后进先出。**

## 008 · 三道树题（101 对称 / 112 路径总和 / 543 直径）

**日期**：2026-11-25　**状态**：⚠️ 会但需巩固（三题一次全过，但缝合法容易混）

### 一、三题对照（同一副骨架，三种缝合）
| 题 | 边界 | 中间 | 缝合 | 返回类型 |
|---|---|---|---|---|
| **100 相同的树** | `p==nil && q==nil → true`<br>`p==nil \|\| q==nil → false` | 比 `p.Val == q.Val` | **同向** `递归(左.Left, 右.Left) && 递归(左.Right, 右.Right)` | `bool` |
| **101 对称二叉树** | 同上 | 比 `左.Val == 右.Val` | **交叉** `镜像(左.Left, 右.Right) && 镜像(左.Right, 右.Left)` | `bool` |
| **112 路径总和** | `节点==nil → false` | 减 `还差-节点.Val` | **或** `有路径(左,剩) \|\| 有路径(右,剩)` | `bool` |
| **543 二叉树的直径** | `节点==nil → 0` | 先算 `左深`、`右深` | **取最大** `max(左深,右深)+1`（答案记外面） | `int` |

### 二、完整正确代码

**101 对称二叉树**
```go
func 对称(root *TreeNode) bool {
	if root == nil {
		return true
	}
	return 镜像(root.Left, root.Right)
}

func 镜像(左 *TreeNode, 右 *TreeNode) bool {
	if 左 == nil && 右 == nil {
		return true
	}
	if 左 == nil || 右 == nil {
		return false
	}
	if 左.Val != 右.Val {
		return false
	}
	return 镜像(左.Left, 右.Right) && 镜像(左.Right, 右.Left)
}
```

**112 路径总和**
```go
func 路径总和(root *TreeNode, targetSum int) bool {
	if root == nil {
		return false
	}
	return 有路径(root, targetSum)
}

func 有路径(节点 *TreeNode, 还差 int) bool {
	if 节点 == nil {
		return false
	}
	if 节点.Left == nil && 节点.Right == nil {
		return 还差 == 节点.Val
	}
	剩下的 := 还差 - 节点.Val
	return 有路径(节点.Left, 剩下的) || 有路径(节点.Right, 剩下的)
}
```

**543 二叉树的直径**
```go
var 答案 int

func 直径(root *TreeNode) int {
	答案 = 0
	深度(root)
	return 答案
}

func 深度(节点 *TreeNode) int {
	if 节点 == nil {
		return 0
	}
	左深 := 深度(节点.Left)
	右深 := 深度(节点.Right)
	if 左深+右深 > 答案 {
		答案 = 左深 + 右深
	}
	return max(左深, 右深) + 1
}

func max(a, b int) int {
	if a > b {
		return a
	}
	return b
}
```

### 三、错在哪 / 卡在哪
1. **101 空 3 写 `左.Val == 右.Val == false`** —— 能跑也对（Go 的 `==` 左结合，等价 `!=`），但团队 review 会被挑，建议用 `!=`
2. **我出题时 112 的测试用例写错** —— 「目标 27」在例1 树上其实有路径（5+4+11+7=27），改成 20 才是否定用例
3. **我出题时 543 的测试用例写错** —— 「左链 [1,2,nil,4,5] 直径 3」实际是 2（4-2-5 只有 2 条边），改成 2

### 四、为什么这么设计（面试话术）
- **为什么 101 要写一个两参数的 `镜像(左,右)`？** 因为对称性本质是「两棵子树之间的关系」，单参数函数表达不了。这和 100 的 `相同的树(p,q)` 同理。
- **为什么 112 必须走到叶子？** 题目定义就是「根到叶子」，中途停下不符合定义。如果允许中途停，那就是「子数组和」类问题，不是路径问题。
- **为什么 543 返回值不能是 `左+右+1`？** 因为对上层来说你只是一条分支，他走不过来你两边。`左+右` 是「路过你」，`max(左,右)+1` 才是「走到你」。**答案和返回值是两个不同的东西，这是 543 唯一的设计难点。**

### 五、三个坑（一句话记住）
1. **101 记牢：左对右、右对左，交叉比** —— 和 100 的左对左只差一个字母
2. **112 记牢：还差逐层减，到叶子看是否为 0**
3. **543 记牢：返回值给上层用 `max+1`，答案记外面用 `左+右`**

### 六、一句话复习点
**树的递归永远是三段：① 到底了返回边界值；② 中间处理（看题）；③ 缝合左右递归。三题只有 ③ 在变：交叉 / 或 / 取最大。**
